# netSentinel ML report — ES 335

## 1. Problem formulation and scope (10)

We classify UNSW-NB15 network-flow records by `attack_cat`. The final four-class question asks whether a record is Normal, Exploits, Fuzzers, or DoS. Analysis and Backdoor were intentionally excluded from this experiment; Generic, Reconnaissance, Shellcode, and Worms were excluded earlier from the six-class benchmark. This is a restricted benchmark, not a detector for all attack types. The [experiment history](MODEL_EXPERIMENT_HISTORY.md) describes both tasks separately.

## 2. Data understanding (10)

The supplied UNSW-NB15 training and test CSVs contain flow-level traffic measurements, protocol/service/state categories, packet and byte counts, timing, and connection statistics. The [data-quality report](results/data_quality_report.json) records raw shapes of 175,341 training and 82,332 test rows, class imbalance, and exact duplicate predictor vectors with conflicting labels. The six-class filter retained 123,587 training and 59,543 test rows. Four-class filtering kept 119,841 training and 58,283 official test rows; 1,260 test rows belonging to Analysis or Backdoor were excluded. These counts define the population to which the reported final test metrics apply.

## 3. Preprocessing and statistical reasoning (10)

The model uses the 42 predictors listed in [selected model metadata](experiments/four_class/models/best_four_class_model_metadata.json). `id` is a row identifier; `label` and `attack_cat` are targets. None is a model input. At prediction time, the pipeline expects the same 42 named flow features, including categorical `proto`, `service`, and `state`; it cannot infer a label from an arbitrary packet or from missing feature definitions.

The [preprocessing notebook](notebooks/01_preprocessing.ipynb) used a stable fingerprint of predictor vectors and a grouped, approximately 80/20 training/validation split with seed 42. Identical predictor vectors were kept in one partition; the recorded group overlap is zero. Four-class experiments reused those saved row indices and then filtered each partition. The fitted pipeline imputes numeric values with training medians, categorical values with training most-frequent values, and one-hot encodes categories with unknown values ignored. Fitting these steps inside the training pipeline prevents validation information from affecting preprocessing. The [four-class notebook](experiments/four_class/01_four_class_experiment.ipynb) documents that workflow.

## 4. Baseline and method selection (15)

The six-class Dummy most-frequent baseline scored 0.1039 validation macro-F1, establishing that accuracy alone was inadequate. Decision Tree, Random Forest, Extra Trees, and HistGradientBoosting baselines were compared; Logistic Regression, Bagging, AdaBoost, and XGBoost were also recorded. The six-class selected candidate was an original Random Forest, but its minority-class recalls remained weak. Those results motivated a separate four-class investigation; its scores are not directly comparable with six-class macro-F1.

On the four-class validation set, the original Decision Tree obtained macro-F1 0.6985, accuracy 0.7951, and conventional normal false-alarm rate 0.0860. Tuned or class-weighted trees and forests improved macro-F1 and DoS/Fuzzers recall but exceeded the stated 10% normal false-alarm preference. The original Decision Tree was therefore retained for the frozen official test evaluation. The later balanced Random Forest achieved validation macro-F1 0.7249 and DoS/Fuzzers recall 0.8304/0.8859, but its corrected false-alarm rate was 0.1583. It remains an alternative operating point, not a replacement chosen from official test results. See [four-class comparison](experiments/four_class/results/model_comparison.csv) and [corrected audit comparison](experiments/four_class/audit/corrected_metric_comparison.csv).

## 5. Evaluation design and metrics (20)

Model configuration was selected from training-only grouped cross-validation and a held-out validation partition. The official test set was kept separate until the selected Decision Tree was retrained from scratch on the eligible training rows and evaluated once in the [final notebook](experiments/four_class/02_final_evaluation.ipynb). There has been no official test evaluation of the improved forest; reusing the observed test set to choose it would make a new score exploratory.

Accuracy is the fraction of all correct predictions. Per-class precision measures how often predictions of that class are correct; recall measures how many actual examples of the class are found; F1 balances the two. Macro-F1 averages class F1 equally, and weighted-F1 weights by class support. The confusion matrix places actual classes in rows and predicted classes in columns. Conventional normal false-alarm rate is `Normal → any attack / all actual Normal = 1 − Normal recall`. Pooled binary attack recall is `actual attacks predicted as any attack / all actual attacks`. The mean of three attack-class recalls is a different metric. The [metric audit](experiments/four_class/audit/metric_audit.md) supplies the corrected values.

## 6. Results, errors, and limitations (10)

**Validation, selected Decision Tree:** macro-F1 0.6985; accuracy 0.7951; normal false-alarm rate 0.0860; pooled binary attack recall 0.9261. **Official test, refitted Decision Tree:** macro-F1 0.5463; accuracy 0.7077; weighted-F1 0.7280; corrected normal false-alarm rate 0.2353; pooled binary attack recall 0.9206. The [test classification report](experiments/four_class/results/final_test_classification_report.csv) gives recall Normal 0.7647, Exploits 0.8217, Fuzzers 0.4474, and DoS 0.2671.

The [test confusion matrix](experiments/four_class/results/final_test_confusion_matrix.csv) shows 7,395 Normal flows labeled Fuzzers and 2,752 DoS flows labeled Exploits; these are prominent error types. The drop from 0.6985 validation to 0.5463 test macro-F1 and the rise in normal false alarms indicate weaker performance on the official test distribution. The refitted model also had more training rows, so this comparison does not isolate distribution shift as the sole cause. Duplicate features with conflicting labels and class imbalance complicate learning. Analysis and Backdoor cannot be reliably identified because the four-class model never learned those labels. Future work could examine data shift, calibration and class-specific errors using new held-out data, while setting an operating preference before evaluation.

## 7. Reproducibility and technical integrity (5)

The saved split, fixed seed, predictor list, train-only transformations, model configuration, result CSVs, and plots support review. Consult the [data-quality report](results/data_quality_report.json), [validation comparison](experiments/four_class/results/model_comparison.csv), [test plot](experiments/four_class/results/plots/final_test_confusion.png), and [audit](experiments/four_class/audit/metric_audit.md). Historical reports contain metric-label errors: the final notebook's `normal_false_positive_rate = 0.0794` divides attacks predicted Normal by actual attacks, so it is an attack false-negative rate. The correct conventional normal false-alarm rate is 0.2353. The improvement CSV similarly reports 0.0071 for the forest under an incorrect formula; the corrected value is 0.1583. Its `attack_recall` is mean attack-class recall. A further error in the existing audit CSV labels the trace of the attack submatrix as `binary_attack_recall`; correct binary detection sums all attack predictions within the attack rows. The improved forest's current notebook states 10 trees while the saved model contains 100; its exact rerun provenance needs reconciliation. Historical artifacts have not been altered for this report.
